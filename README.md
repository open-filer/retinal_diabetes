# Retinal Diabetes Detection

An educational Streamlit application with two independent screening experiences:

- **Specialist retinal analysis:** run one or more deep-learning models on a retinal fundus image to estimate the likelihood of diabetic retinopathy.
- **General diabetes-risk screening:** estimate diabetes risk from common health measurements using an ensemble of classical machine-learning models.

> **Medical disclaimer:** This is an educational project, not a certified diagnostic device. Do not use it to make medical decisions.

## What is included

| Path | Purpose |
| --- | --- |
| `app.py` | Streamlit interface |
| `ensemble_utils.py` | Retina-model loading, preprocessing, and ensemble inference |
| `general_risk/` | General-risk model code and evaluation metadata |
| `results/` | Retina model evaluation metrics used by the dashboard |
| `static/` | User-interface video assets |

## Required local model artifacts

Model weights are intentionally excluded from Git to keep the repository lightweight and to avoid publishing trained artifacts by accident. Before running predictions locally, obtain the approved model artifacts and place them in these paths:

```text
models/*.keras
models/*.pt
general_risk/trained_models.joblib
```

The current general-risk artifact can also be generated by running `general_risk/train_models.py` from that directory with a compatible `diabetes.csv` dataset. The training dataset is not included in this repository.

## Run locally

Use Python 3.10 or 3.11 (TensorFlow support is typically most reliable on these versions).

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m streamlit run app.py
```

## Secrets and external services

The application uses no API keys, backend API calls, databases, or cloud credentials. It only loads a public Google Fonts stylesheet in the browser. `.env` files and Streamlit's `secrets.toml` are ignored so credentials added later cannot be committed accidentally.

## Deployment note: Cloudflare Pages

Cloudflare Pages hosts static sites and Pages Functions run JavaScript/TypeScript at the edge. This application is a stateful Python/Streamlit service that requires TensorFlow, PyTorch, timm, scikit-learn, and local model files, so it **cannot run directly on Cloudflare Pages**.

Recommended options:

1. Deploy the Streamlit app to a Python/container host (for example, Streamlit Community Cloud, Render, Railway, Fly.io, or a VM) and keep the model artifacts in private storage.
2. If Cloudflare Pages is mandatory, redesign the application: host inference behind a separate container API, then deploy a static JavaScript frontend to Pages that calls that API. Do not expose inference credentials in the frontend.

## Repository hygiene

- Do not commit `.env`, `.streamlit/secrets.toml`, or model weights.
- Use a private model registry/object store or Git LFS for approved model artifacts.
- Review the medical disclaimer and model licensing before making a public deployment.
